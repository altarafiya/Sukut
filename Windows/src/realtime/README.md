# Step 5 worker contract

`cleanwave_realtime` contains the Audio processor, timing-only recovery policy and a bounded capture/process/playback pipeline. The core does not call Windows audio APIs. Step 6 provides `StreamInput` and `StreamOutput` WASAPI adapters under `src/audio/`.

Adapters expose their sample rate; Start rejects anything other than 48 kHz. Open and Close run on the owning capture/playback thread, including error cleanup. Playback Open completes before the readiness barrier allows capture; normal output EOS invokes Finish before Close, while cancellation skips drain and closes promptly. This preserves WASAPI's COM/client/service ownership requirements. Refer to `src/audio/README.md` for the native contract.

The format is always 48 kHz stereo PCM16. Capture assembles 1536 frames for the first packet and 960 frames thereafter. Each output packet contains 960 frames. Reads/writes return frame counts, not sample or byte counts; stereo frames must remain intact. Output callbacks receive the absolute first output-frame index, including the offset within a partial write.

Capture and playback each have a three-packet queue. Input/output pools each contain five fixed packets, including the first packet; no per-packet buffer allocation occurs in the worker core. Backpressure has a configurable deadline (default one second) and zero-progress I/O has a separate deadline (default 200 ms). Saturation and adapter/model errors retain the first failure and cancel all workers.

Start runs model/FFT warmup on the process worker and waits for process and playback readiness before launching capture. Warmup uses one 1536-frame silent packet and three 960-frame silent hops, then resets all analysis/model/tail/level/recovery state. The source mix is preserved. Configuration updates replace the complete mix tuple under one mutex; the process worker snapshots it once per hop and owns DSP/model/level state exclusively.

The Audio policy counts decode plus analysis FFT, model inference, remix, inverse FFT and synthesis against 20 ms. Two consecutive over-budget AI runs fade toward aligned original audio and reset neural state plus synthesis tail while preserving analysis history. Thirteen bypass hops implement `ceil(250/20)` cooldown. A failed probe resets and restarts cooldown; two healthy probes restore wet audio through the existing level ramp. Queue occupancy is deliberately not an overload input. Cheap bypass timings are reported separately from AI timings.

The pipeline measures the entire processor callback separately, including configuration, level rendering, state reset and processor telemetry overhead. Queue/I/O waits, initialization/warmup and capture-to-playback delay are excluded from both processing timing categories. Summaries use nearest-rank percentiles over the latest up to 4096 samples; counts/mean/max/budget misses cover the whole stream. Snapshot percentile sorting and allocations happen outside the worker statistics lock. Live queue sizes are sampled individually; a post-join snapshot is the consistent final state.

Step 8 registers the live process worker with the existing Windows Pro Audio MMCSS task at AVRT_PRIORITY_CRITICAL and disables execution-speed throttling for that worker (HighQoS). Registration/errors are reported. The worker restores/reverts its own policy at the end; process priority, CPU affinity, system power plans and registry settings are untouched. Standalone fixture workers keep this option off by default; LiveSession enables it.

The Step 8 seek correction adds an optional finite burst allowance to recovery. LiveSession opts into 40 ms from its existing 60 ms render reserve. Each run hop consumes credit for engine time above 20 ms, or refills credit for time below 20 ms, capped at 40 ms. Covered overruns retain wet output and neural state. Two consecutive uncovered misses still trigger fallback; the 13-hop cooldown and two strictly under-or-equal-to-20-ms probes remain. Reset retains the configured policy and primes its finite allowance; healthy recovery restores it after the bypass cooldown. Standalone cleaners and default RecoveryController retain the original strict timing policy. Raw elapsed timings are always reported without subtracting credit. This is a live recovery-trigger change awaiting user testing; it changes neither model/DSP arithmetic nor native buffer durations.

CPU accounting from GetThreadTimes is diagnostic only. On this host it changes in coarse 15.625 ms increments, so per-hop CPU percentiles do not prove scheduling stalls. The elapsed-minus-CPU mean is a whole-run accounting comparison, may be negative over short windows and never drives recovery. The live budget still uses monotonic elapsed decode/DSP/model time.

`Start`, `WaitStopped` and destruction belong on the controlling thread, never inside an adapter/processor callback. `RequestStop` is safe during startup, I/O, queue/pool waits or processing. `WaitStopped` has a deadline, including acquiring the lifecycle lock. The adapters must honor their stop token promptly and interrupt native blocking I/O; the worker core cannot forcibly interrupt an uncooperative adapter or an in-flight TensorFlow Lite invocation. Destruction joins workers, so cooperative adapters and returning processor calls are required. Call `WaitStopped` before treating shutdown as complete or reusing stream resources. Restart resets pools and processor state after all old workers join.

`ReadStatus::End` drains complete continuous packets. EOS inside a partial packet is an explicit error. A continuous stream retains 576 frames of future context after its last complete packet. Finite-file zero-context/trim/tail scheduling remains the separate `OfflinePipeline` contract; do not use this worker interface as a finite WAV renderer without that scheduler.

The verifier covers deterministic policy/fade cases, partial I/O, transient/permanent stalls, bounded saturation, failure cleanup, consumer-first startup, blocked-I/O/startup cancellation, repeated streams, real-model warmup/reset parity, concurrent mix updates and a synthetic stream scheduled against absolute 20 ms deadlines. Its source and sink are in memory. Successful verification does not establish live Windows routing, end-to-end latency, listening quality or endurance.

Step 7 adds Off/Default/Custom without changing the waveform math: Off outputs exact aligned dry PCM and skips inference; Default uses the fixed tuple; Custom is separately retained across mode changes/restart. Timings categorize Off and recovery bypass together, with off_packets identifying the user mode. Recovery counts survive mode/segment resets within a stream. Warmup resets stream metrics.

ReadResult.discontinuity marks fresh data from a new segment. Capture discards its unfinished old packet, moves new samples to the start, gathers 1536 frames and marks first. A repeated first resets Audio analysis/neural/tail/level/recovery state. Complete queued packets retain order; output indexes count submitted frames, without pretending to recover the unknown driver gap. Counters expose segment resets, discarded partial frames and discarded future context. Deterministic partial I/O verifies exact original segment order and both pools returning 5/5. Live integration and its independent source process are documented in src/live/README.md.
